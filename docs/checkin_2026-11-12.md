# Notes for the Nov 12 check-in

Facts to report at the mid-project check-in, collected as the milestones are done. The milestones from the
final abstract: "data pipeline validated against The Well's released checkpoints, budgets fixed from pilot
timings, and first 10%-data results with a revised plan." Details and reasoning are in `docs/decisions.md`
(D numbers below).

## 1. Data pipeline validated against The Well's released checkpoints: done

Passed 2026-11-08 (HPC3 job 59224204, one A100). We loaded The Well's released CNextU-Net and TFNO weights
into our own models and scored them with our own data loading and evaluation (one-step VRMSE, field mean,
every window of every trajectory, physical units). The criterion was "ours ≤ published" (owner, 2026-11-08).

| Model | Ours: valid / test | Published: valid / test |
|---|---|---|
| CNextU-Net | 0.234 / 0.224 | 0.481 / 0.670 |
| TFNO | 0.305 / 0.300 | 0.857 / 0.657 |

What else was checked (D20):
* Same data as the paper: the server's files are dated 2024-12-05 (the original release), with the official
  splits (1400 / 175 / 175 trajectories) and the same normalisation statistics (`stats.yaml` v1.0.1).
* Same code source: models, normalisation and VRMSE from `github.com/PolymathicAI/the_well`, pinned at
  `e63dec8`. Our rollouts equal upstream's exactly (max difference 0.0; VRMSE equal to NumPy within 1e-7).
* The released configs equal ours, and the weights load strictly (no missing or extra parameters).

Caveats to state:
* **The paper's TFNO never used its Fourier layers.** From 2024-06-03 until upstream commit `e430160`
  (2025-11-17) the TFNO wrapper discarded the Fourier blocks' output, so the paper's TFNO and the released
  checkpoint are a per-pixel MLP (lifting → projection). With the current code the checkpoint gives noise
  (VRMSE 10.7), so it was scored with the forward pass it was trained with. Our TFNO, with working Fourier
  layers, is a different and stronger model. Upstream issue #49 (open) acknowledges outdated paper numbers.
* **The published values could not be reproduced exactly, only beaten.** Emulating the paper's protocols
  gives, for CNextU-Net and TFNO: validation (20 shuffled batches, normalised units) 0.70 and 0.68; test with
  the v1.0.1 unnormalised-test bug 9.99 and 1.18. Neither matches the published numbers.
* Data loading had to be rewritten for speed (D23); samples are bitwise identical to upstream's.

### The released checkpoints

Downloaded from Hugging Face at pinned revisions, with the weights' SHA-256 checked (`src/rbbench/released.py`):
* CNextU-Net: `polymathic-ai/UNetConvNext-rayleigh_benard`, revision `c5fa0f7a50aca21b65fed95e0f7e8d1097eb2b8b`
* TFNO: `polymathic-ai/TFNO-rayleigh_benard`, revision `7d351350eaf68caba1eac1e545cd6661251dd1fd`

From the model cards at those revisions (read 2026-11-08):

| | CNextU-Net | TFNO |
|---|---|---|
| Training | 12 h or 500 epochs, whichever first | same |
| Hardware | one NVIDIA H100 96 GB | same |
| Checkpoint | best on validation, epoch 12 | best on validation, epoch 31 |
| Learning rate | 5e-4, best of 5 tried | 1e-4, best of 5 tried |
| Input frames | 4 | 4 |
| Batch size | "set to maximize the memory usage" | same |
| Published VRMSE (valid) | 0.4807 | 0.8568 |
| Seed | not stated | not stated |
| Training date | not stated | not stated |

From our own checks:
* Both repositories were created on 2025-03-28. The paper's tables already contain these numbers, so the
  training itself presumably happened in 2024.
* The TFNO checkpoint only works with the paper-era forward pass, so it comes from the paper-era code.
* Batch size: the card says it was set to fill memory, while The Well's `rayleigh_benard` data config says 64
  (which we use). The exact batch of these runs is uncertain.
* One run per model with an undocumented seed: the published numbers carry no seed-to-seed spread. Our study
  uses two seeds.

## 2. Budgets fixed from pilot timings: in progress

Fixed so far:
* Budgets 1 h and 4 h of training on one A100 (final abstract).
* Batch 64 and fp32 for every model; batch 64 fits all in A100 80 GB memory (peak CNextU-Net 58.7 GB, TFNO
  44.9, AViT 7.4) (D7, D8). TFNO cannot use bf16 (D8).
* The budgets count GPU training time only (owner, 2026-11-08; D24). Storage (`/pub`) delivers ~98 samples/s
  into one node (D23): CNextU-Net never waits, but AViT could use ~170 and would otherwise lose about half its
  steps. Waiting time is logged and reported separately, with the real (wall) hours.
* Learning rates from an equal-budget search on validation (owner, 2026-11-08; D7): each model tries 1e-4,
  5e-4, 1e-3 for 20 min of GPU time on the 10% subset, seed 0, and keeps the lowest validation loss.

Still to add: the search results and the pilot timings table from `rbbench select-lr` (GPU s/step, share of
time waiting for data, steps and epochs in 1 h and 4 h, real hours per run).
